**Security fix: upgrade if you use the context graph.** In 0.1.3 and earlier, with the [context graph](/docs/context-graph/) on, `search(user_id="alice")` could return another user's memories: topic links joined memories of different users, and graph search did not check whose memory it reached. Graph search now stays within the `user_id`, `agent_id`, and `run_id` you pass, and new links only join memories of the same user and agent. A graph built before 0.1.4 can still hold links between users; search ignores them, and `reset_context_graph()` followed by `backfill_context_graph()` removes them.

- **[State store](/docs/configuration/#state-store)** (`state_store`): keep the context graph, personalized-retrieval feedback, and cold storage in Postgres, so several processes share them and a restart loses nothing. Install with `pip install "outhad-contextkitai[postgres]"`.
- **[Episodic memory](/docs/episodic-memory/)** (`tcmgm`), available on request: `build_timeline`, `get_timeline`, and `get_causal_chain` on `Memory` and `AsyncMemory`, with settings for storing events on every `add()` and for how cause → effect links are found.
- `AsyncMemory.search` takes `use_tcmgm`, `time_window`, and `include_causal`, like `Memory.search`.
- Fixed: cause → effect links between events were never stored, so causal chains came back empty.
- Fixed: `AsyncMemory.add(..., infer=False)` raised `AttributeError`.
