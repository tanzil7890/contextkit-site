This is ContextKit→

A memory layer for AI agents. Instead of resending the whole conversation every turn, your agent stores facts once and pulls back only the handful that matter for the request in front of it.

How it works

Two calls do most of the work: add when something is said, and search before your agent answers. Everything else is an option on one of them.

add messages→ extract facts→ compare with stored→ ADD · UPDATE · DELETE→ store + history
search query→ search in scope→ expand links · optional→ re-rank · optional→ top memories → prompt

Facts, not transcripts

The LLM keeps “Allergic to peanuts”, not the five messages it came from. When a fact changes, the old memory is updated instead of contradicted. Pass infer=False to store text as-is.

Scoped by default

Every memory belongs to a user_id, agent_id, or run_id, and every search stays inside one. Add your own metadata and filter on it too.

Every change on record

Each add, update, and delete writes a history row with the old and new text, so history(memory_id) shows how a fact changed and when.

Kinds of memory

An agent needs to remember different things for different lengths of time. Each kind below is a scope or a feature of the same library, so you can mix them in one store.

long-term · facts

User memory

Preferences, constraints, and history about a person that should outlive any one conversation.

via user_id

“Allergic to peanuts”

short-term · working

Session memory

What matters for one task, ticket, or run, and nothing else. Clear it when the job is done.

via run_id

“Wants the refund on the original card”

shared

Agent memory

What one agent learned across the people it serves, or what several agents share on one job.

via agent_id

“Login builds SQL by concatenation”

how-to

Procedural memory

How the agent got something done, summarised from its own steps, so the next run goes faster.

via memory_type

“Search → refundable only → hold seat”

events · timeline

Episodic memory{{ soon("episodic-memory") }}

What happened, when, and what led to what: dated events with cause → effect links.

via build_timeline

“Cache shipped Mon → timeouts Tue”

entities · graph

Relational memory

People, products, and services and how they connect, kept in Neo4j, Memgraph, or Neptune.

via graph_store

alice → works_at → acme

reference

Document memory

Handbooks, transcripts, and logs stored as written, split into chunks, rejoined when found.

via infer=False

“Refunds within 30 days of delivery…”

images

Visual memory

Screenshots, photos, and designs, described by a vision model and kept as searchable facts.

via enable_vision

“Spring packaging is sage green”

Layers you turn on when you need them

The core needs an LLM and a vector store. Every layer below is off until you enable it, and off means no change in behaviour, so you can start small and add one at a time.

Core · always on

Memory engine

Fact extraction, add / update / delete decisions, scoped vector search, metadata filters, and a history row for every change.

Needs an LLM, an embedder, and a vector store. Qdrant on local disk works with no servers.

Retrieval · what comes back

Graph memory{{ soon("graph-memory") }}

Entities and relations in a graph database, stamped with when they were recorded and searched together with the vectors.

Use it for questions about who and what is connected: people, accounts, products, services.

"graph_store"Guide →

Episodic memory{{ soon("episodic-memory") }}

Dated events and the cause → effect links between them, kept on top of graph memory, so your agent can answer when and why.

Use it for incidents, case histories, and projects: “why did checkout start timing out?”

"tcmgm"Guide →

Context graph{{ soon("context-graph") }}

Links memories to each other (replies, timeline order, shared documents, similar topics) and searches through the links, so the context around a match comes back with it.

Use it for long conversations where one fact only makes sense next to its neighbours.

"context_graph"Guide →

Personalized retrieval{{ soon("personalized-retrieval") }}

Feedback, usage, answers that worked before, and the kind of question each add a weighted signal to the ranking. Every weight starts at zero.

Use it for assistants that should get better the more they are used.

Get started

  1. Install with the command above. Python 3.9 or newer.
  2. Set a model key: export OPENAI_API_KEY=sk-…. OpenAI is the default; Anthropic, Gemini, Groq, Ollama, and others are a config change away.
  3. Store what the user says with memory.add(messages, user_id="alice").
  4. Search before each reply with memory.search(query, user_id="alice"), and put the results in your prompt.
